直连规则：让测试结果更干净

让测试用的域名不走代理（直连），测出来的才是你自己的线路。这些规则只匹配测试域名，其他流量照旧。

    原理和常见问题

    为什么从你自己的网络测，比测速网站和 Looking Glass 更准

    结论：想知道你用起来快不快，就得从你自己的网络测。

    大部分「云服务器测速」网站，以及厂商自己的 Looking Glass，都是从他们的服务器发起测试。这些服务器在机房里，接的是优质线路，测出来的只是「机房到机房」有多快。你真正感受到的那一段，家里的宽带或手机网络、运营商骨干网、国际出口、今晚堵不堵，它们都测不到。

    Me2Cloud 的每个请求都从你的浏览器发出，所以 Wi‑Fi、路由器、运营商、运营商选的线路和晚高峰，全都算在结果里。

    每次采样是怎么测的

    1. 先发一次预热请求，把 DNS 查询、TCP 连接和 TLS 加密都建好。这次的时间会显示出来，但不算进结果。
    2. 然后在同一条连接上，对同一个主机再发 5、10 或 20 次请求。每次只花一个来回，加上厂商服务器很短的处理时间。
    3. 每家厂商都用我们实测过、能保持连接的请求方式：AWS、Azure、Google Cloud、DigitalOcean、Scaleway 用 GET；Oracle、IBM Cloud、阿里云、腾讯云、火山引擎、百度智能云、Naver Cloud、华为云、Linode、Vultr、OVHcloud、IONOS Cloud、Aruba Cloud、Leaseweb、Gcore、Yandex Cloud 用 HEAD（它们收到 GET 会断开连接，每次采样会变成原来的 3 倍左右）；Hetzner 用 CORS 方式的 GET，否则浏览器会截断它返回的网页并断开连接。
    4. 结果给出中位数（最典型的那个值）、平均值、P90（10 次里有 9 次不超过它）、抖动（相邻两次相差多少，取平均）和超时率（在时限内没有回应的比例）。
    5. 分档按中位数来：T0 夯 ≤ 30 ms、T1 顶级 ≤ 80 ms、T2 人上人 ≤ 150 ms、T3 NPC ≤ 250 ms，再往上就是 T4 拉完了。「给你挑的」按「中位数 + 2 × 抖动 + 超时扣分」排序，所以稳定的 60 ms 会排在忽高忽低的 45 ms 前面。

    为什么用 HTTPS 测，比 ICMP ping 更接近真实体验

    • 和你的流量走同一条路。网页、API、走 443 端口的隧道、游戏登录、下载，用的都是 TCP。不少运营商会单独给 ICMP 排队、限速，甚至让它走另一条线路，所以常常 ping 看着挺好，网页却很卡，反过来也有。
    • 不容易被限速。路由器和云厂商经常限制甚至直接丢掉 ICMP，访问公开的 HTTPS 地址则总会有回应。
    • 算上你的真实环境。DNS、IPv4 还是 IPv6、代理、加速器，都会作用在浏览器的流量上，测出来的就是你实际能拿到的效果。
    • 代价是：每次采样还包含一点很稳定的服务器处理时间。我们实测 AWS 是 0–5 ms，阿里云约 8 ms，华为云 OBS 约 20 ms。延迟上百毫秒时完全可以忽略；离你特别近的区域，数字会比 ping 略高一点。

    什么时候测：专挑晚高峰

    • 家里的宽带在晚上 20:00–23:00 最堵，出国线路更明显。中午还是 T1 顶级的区域，到了晚上可能直接掉到 NPC。
    • 建议白天测一次，晚高峰再测一次。晚高峰的结果会打上「晚高峰」标签，在测试结果里可以来回切换对比。
    • 测试时先暂停大文件下载、视频和网盘同步。插网线比 Wi‑Fi 准；只能用 Wi‑Fi 的话，尽量离路由器近一点。
    • 用手机流量测，结果会随信号变化。最好在你真正要用的地方测。

    适合用来做什么

    • 买云服务器、游戏服务器或 CDN 回源之前，先把候选区域筛一遍。
    • 比较同一家厂商的不同区域，或者同一座城市里不同厂商的表现。
    • 看看稳定性（抖动、超时率）够不够打游戏、开视频会议、用远程桌面和 SSH。
    • 验证你的代理、加速器或新办的宽带到底行不行：开着测一次，关掉再测一次。
    • 用自定义测速点，把你自己的服务器或 CDN 和大厂放在一起比。

    它做不到的事

    • 只代表你这一个位置。测的是你的线路，不是你用户的。可以请几个用户也测一下，导出来对比。
    • 测的是厂商的公共地址，不是你以后的云服务器。我们测的是厂商在这个区域的公开 API 或存储地址。同一个区域的服务器一般共用网络，但精品线路（比如 CN2、BGP 和单线、Lightsail 和 EC2）可能不一样。
    • 不测带宽，不测 UDP，也不做路由追踪。只测来回时间，测不了下载速度和 UDP 游戏流量，也看不到中间经过了哪些节点。要测下载速度，可以用网速测试。
    • 浏览器本身会带来误差。插件、代理、VPN、很忙的标签页都会让结果有波动。测试时关掉占资源的标签页，让本页一直在前台。
    • 少数测速地址在个别国家和地区可能访问不了。

    隐私：测试请求都从你的浏览器发出，结果不上传

    • 测试结果不会上传，也不用注册。只有你点「分享结果」时，结果才会存成一条短链接和一张预览图，放在 1ms.dog 上，方便在聊天软件里打开。
    • 每个测试请求都由你的浏览器直接发给厂商。打开上面的请求记录，或者浏览器开发者工具的 Network（网络）面板，每一条都看得到。
    • 网络信息来自 Cloudflare：本站的 /_ms/me 先给出结果，最终以 speed.cloudflare.com/meta 和 /cdn-cgi/trace 为准，因为它们和测试走同一条路。可选的 WebRTC 检测会向 stun.cloudflare.com 询问你的 UDP 出口地址，不想用可以在设置里关掉。
    • 检测 IPv4/IPv6 时，还会问 Cloudflare 以外的 ipify.org 和 ident.me。这样某一家被网络屏蔽时，不会被误判成没有 IPv6。
    • 页面出错时，会把错误信息、页面地址和浏览器型号发回本站，用来修问题；用分享功能时会匿名记一次用到了哪一步。这些都不包含你的测试结果。
    • 设置、自定义测速点和最近几次结果只存在这个浏览器里。按住「清空测试数据」会删掉结果和历史；想连设置一起删，清除本站的浏览器数据就行。

    对厂商友好：不会触发限流，也不会被封

    对公开地址请求太猛，可能触发厂商的限流或防火墙（WAF），结果也就不准了。所以测试节奏刻意压得很低：

    • 每个主机同一时间只有一个请求，两次采样之间停 250–370 ms（每个主机每秒最多 2–3 个请求）。
    • 每家厂商最多同时测 2 个主机，总共最多 8 个（默认 4 个）。
    • 每次测试，每个主机最多 21 个请求（预热 1 次 + 最多 20 次），没有持续不停的模式。
    • 连续失败 3 次就放弃这个主机，不会反复重试。
    • 全部是匿名请求：不带 Cookie，不带来源页，也不需要预检；回应只有几百字节，能用 HEAD 就用 HEAD，不下载大文件。

    整个过程的流量比打开一个普通网页还少。每个测速地址都验证过能正常回应匿名请求（返回 200、403 还是 404 都不影响计时）。

    开着代理或 VPN 怎么办？

    流量走代理时，浏览器测到的是「你到代理」加上「代理到厂商」，不是你自己的线路。网络面板会检查几个常见迹象：出口网络属于机房、时区和出口国家对不上、开着 WARP、WebRTC 出口和 HTTPS 出口不一样。

    点获取直连规则，只让测试域名直连（支持 Clash / Mihomo、Surge、Shadowrocket、Quantumult X、Loon、sing-box、Xray、SwitchyOmega 和纯域名列表），然后重新检测。如果你想测的就是代理本身，那就开着测，得到的就是代理的真实表现。

    怎么看图

    • 每一行的条形图都用同一把尺子（对数刻度，2 ms 到 3 s）。圆点是每次采样，阴影框是中间一半采样所在的范围，竖线是中位数。
    • 框越窄越稳；框很宽或者点很散，就是抖得厉害。红色 × 表示超时的次数。
    • 点开一行，能看到每次采样的先后变化、全部统计数据和用到的测速地址。✓ 表示符合你的要求。
