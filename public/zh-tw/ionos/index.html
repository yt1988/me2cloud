直連規則：讓測試結果更乾淨

讓測試用的網域不經過代理（直連），測出來的才是你自己的線路。這些規則只比對測試網域，其他流量維持原樣。

    原理和常見問題

    為什麼從你自己的網路測，比測速網站和 Looking Glass 更準

    結論：想知道你用起來快不快，就要從你自己的網路測。

    大部分「雲端測速」網站，以及業者自己的 Looking Glass，都是從他們的伺服器發起測試。這些伺服器在機房裡，接的是高品質線路，測出來的只是「機房到機房」有多快。你真正感受到的那一段，家裡的寬頻或行動網路、電信業者的骨幹網路、國際出口、今晚塞不塞，它們都測不到。

    Me2Cloud 的每個請求都從你的瀏覽器送出，所以 Wi‑Fi、路由器、電信業者、業者選的路線和晚間尖峰，全都算在結果裡。

    每次取樣是怎麼測的

    1. 先送一次暖機請求，把 DNS 查詢、TCP 連線和 TLS 加密都建立好。這次的時間會顯示，但不算進結果。
    2. 接著在同一條連線上，對同一台主機再送 5、10 或 20 次請求。每次只花一個來回，再加上業者伺服器很短的處理時間。
    3. 每家業者都用我們實測過、能維持連線的請求方式：AWS、Azure、Google Cloud、DigitalOcean、Scaleway 用 GET；Oracle、IBM Cloud、阿里雲、騰訊雲、火山引擎、百度智能雲、Naver Cloud、華為雲、Linode、Vultr、OVHcloud、IONOS Cloud、Aruba Cloud、Leaseweb、Gcore、Yandex Cloud 用 HEAD（它們收到 GET 會中斷連線，每次取樣會變成大約 3 倍）；Hetzner 用 CORS 模式的 GET，否則瀏覽器會截斷它回傳的網頁並中斷連線。
    4. 結果會列出中位數（最典型的值）、平均值、P90（10 次裡有 9 次不超過它）、抖動（相鄰兩次差多少，取平均）和封包遺失（逾時沒有回應的次數）。
    5. 分級依中位數：T0 神 ≤ 30 ms、T1 頂級 ≤ 80 ms、T2 很可以 ≤ 150 ms、T3 路人 ≤ 250 ms，再往上就是 T4 爛掉了。「幫你挑的」依「中位數 + 2 × 抖動 + 封包遺失扣分」排序，所以穩定的 60 ms 會排在忽高忽低的 45 ms 前面。

    為什麼用 HTTPS 測，比 ICMP ping 更接近實際體驗

    • 和你的流量走同一條路。網頁、API、走 443 埠的通道、遊戲登入、下載，用的都是 TCP。不少電信業者會讓 ICMP 另外排隊、限速，甚至走另一條路線，所以常常 ping 看起來不錯，網頁卻很卡，反過來也有。
    • 不容易被限速。路由器和雲端業者常會限制甚至直接丟掉 ICMP，但公開的 HTTPS 網址一定會回應。
    • 算進你的實際環境。DNS、走 IPv4 還是 IPv6、代理、加速器，都會作用在瀏覽器的流量上，測出來的就是你實際能拿到的效果。
    • 代價是：每次取樣還包含一點很穩定的伺服器處理時間。我們實測 AWS 是 0–5 ms，阿里雲約 8 ms，華為雲 OBS 約 20 ms。延遲上百毫秒時完全可以忽略；離你特別近的區域，數字會比 ping 稍高一點。

    什麼時候測：挑晚間尖峰

    • 家用寬頻在晚上 20:00–23:00 最塞，國際線路更明顯。中午還是 T1 頂級的區域，到了晚上可能直接掉到 T3 路人。
    • 建議白天測一次、晚間尖峰再測一次。尖峰時段的結果會標上「晚間尖峰」，在測試結果裡可以來回切換比較。
    • 測試時先暫停大檔案下載、影片和雲端硬碟同步。接網路線比 Wi‑Fi 準；只能用 Wi‑Fi 的話，盡量靠近路由器。
    • 用行動網路測，結果會隨訊號變化。最好在你真正要用的地方測。

    適合用來做什麼

    • 買雲端伺服器、遊戲伺服器或 CDN 來源站之前，先把候選區域篩過一輪。
    • 比較同一家業者的不同區域，或同一座城市裡不同業者的表現。
    • 看看穩定度（抖動、封包遺失）夠不夠玩遊戲、開視訊會議、用遠端桌面和 SSH。
    • 驗證你的代理、加速器或新申辦的寬頻到底好不好：開著測一次，關掉再測一次。
    • 用自訂測速點，把你自己的伺服器或 CDN 和大廠放在一起比。

    它做不到的事

    • 只代表你這一個位置。測的是你的線路，不是你使用者的。可以請幾位使用者也測一下，匯出來比較。
    • 測的是業者的公開網址，不是你之後的雲端主機。我們測的是業者在該區域的公開 API 或儲存服務網址。同區域的伺服器通常共用網路，但精品線路（例如 CN2、BGP 和單線、Lightsail 和 EC2）可能不同。
    • 不測頻寬、不測 UDP，也不做路由追蹤。只測來回時間，測不了下載速度和 UDP 遊戲流量，也看不到中間經過哪些節點。要測下載速度，可以用網速測試。
    • 瀏覽器本身會帶來誤差。擴充功能、代理、VPN、很忙的分頁都會讓結果有波動。測試時關掉吃資源的分頁，讓本頁保持在前景。
    • 少數測速網址在部分國家和地區可能連不上。

    隱私：測試請求都從你的瀏覽器送出，結果不上傳

    • 測試結果不會上傳，也不用註冊。只有你按「分享結果」時，結果才會存成一個短網址和一張預覽圖，放在 1ms.dog 上，方便在聊天軟體裡開啟。
    • 每個測試請求都由你的瀏覽器直接送給業者。打開上面的請求紀錄，或瀏覽器開發人員工具的 Network（網路）分頁，每一筆都看得到。
    • 網路資訊來自 Cloudflare：本站的 /_ms/me 先給出結果，最後以 speed.cloudflare.com/meta 和 /cdn-cgi/trace 為準，因為它們和測試走同一條路。可選的 WebRTC 檢測會向 stun.cloudflare.com 詢問你的 UDP 出口位址，不想用可以在設定裡關掉。
    • 檢測 IPv4/IPv6 時，也會詢問 Cloudflare 以外的 ipify.org 和 ident.me。這樣其中一家被網路封鎖時，不會被誤判成沒有 IPv6。
    • 頁面出錯時，會把錯誤訊息、頁面網址和瀏覽器版本傳回本站，用來修正問題；使用分享功能時，會匿名記錄用到哪些步驟。這些都不包含你的測試結果。
    • 設定、自訂測速點和最近幾次結果只存在這個瀏覽器裡。長按「清除測試資料」會刪掉結果和歷史紀錄；想連設定一起刪，清除本站的瀏覽器資料就可以。

    對業者友善：不會觸發限流，也不會被封鎖

    對公開網址請求得太猛，可能觸發業者的限流或防火牆（WAF），結果也就不準了。所以測試節奏刻意壓得很低：

    • 每台主機同一時間只有一個請求，兩次取樣之間停 250–370 ms（每台主機每秒最多 2–3 個請求）。
    • 每家業者最多同時測 2 台主機，總共最多 8 台（預設 4 台）。
    • 每次測試，每台主機最多 21 個請求（暖機 1 次 + 最多 20 次），沒有持續不停的模式。
    • 連續失敗 3 次就放棄這台主機，不會一直重試。
    • 全部是匿名請求：不帶 Cookie、不帶來源頁，也不需要預檢；回應只有幾百位元組，能用 HEAD 就用 HEAD，不下載大檔案。

    整個過程的流量比打開一個普通網頁還少。每個測速網址都驗證過能正常回應匿名請求（回傳 200、403 或 404 都不影響計時）。

    開著代理或 VPN 怎麼辦？

    流量走代理時，瀏覽器測到的是「你到代理」加上「代理到業者」，不是你自己的線路。網路面板會檢查幾個常見跡象：出口網路屬於機房、時區和出口國家對不上、開著 WARP、WebRTC 出口和 HTTPS 出口不同。

    按取得直連規則，只讓測試網域直連（支援 Clash / Mihomo、Surge、Shadowrocket、Quantumult X、Loon、sing-box、Xray、SwitchyOmega 和純網域清單），然後重新檢測。如果你想測的就是代理本身，那就開著測，得到的就是代理的實際表現。

    怎麼看圖

    • 每一列的長條圖都用同一把尺（對數刻度，2 ms 到 3 s）。圓點是每次取樣，陰影框是中間一半取樣所在的範圍，直線是中位數。

    • 點開一列，可以看到每次取樣的前後變化、全部統計數據和用到的測速網址。✓ 表示符合你的條件。

    在伺服器上也測一下

    在 VPS、Linux 主機或路由器上執行這行指令，就能從那裡測同樣這些區域。預設用 TCP 交握計時（也可以用 ICMP），大約 1 分鐘測完，最後給你一個結果連結，在這裡就能開啟。
