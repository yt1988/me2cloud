直結ルール：テスト結果をクリーンに

テスト用のホストを直結にすると、プロキシではなく自分の回線を測れます。ルールはテスト用ホストだけに一致し、ほかの通信には影響しません。

    しくみとよくある質問

    自宅の回線から測るほうが、速度テストサイトや Looking Glass より信頼できる理由

    多くの「クラウド速度テスト」サイトや各社の Looking Glass は、彼らのサーバーから測ります。データセンターに置かれた高品質回線のサーバーなので、わかるのは「データセンター間」の速さだけ。あなたが実際に体感する部分、つまり自宅の回線やモバイル回線、プロバイダの基幹網、国際回線、そして今夜の混み具合は測れません。

    Me2Cloud はすべてのリクエストをあなたのブラウザから送ります。Wi‑Fi、ルーター、プロバイダ、プロバイダの経路選び、夜のピークまで、全部が結果に入ります。

    1 回ごとの測り方

    1. まずウォームアップのリクエストで DNS、TCP、TLS を確立します。この時間は表示しますが集計には入れません。
    2. 続けて同じ接続で同じホストに 5・10・20 回リクエストします。1 回あたり往復 1 回分と、クラウド側の処理時間だけがかかります。
    3. 各社とも、接続を保てることを確かめた方式を使います：AWS、Azure、Google Cloud、Huawei Cloud、DigitalOcean、Scaleway は GET、Oracle、IBM Cloud、Alibaba Cloud、Tencent Cloud、Volcengine、Baidu AI Cloud、Naver Cloud、Linode、Vultr、OVHcloud は HEAD（GET だと接続が切れて 3 倍になる）、Hetzner だけ <img>。
    4. 結果は中央値（いちばん典型的な値）、平均、P90（10 回中 9 回はこれ以下）、ジッター（連続する 2 回の差の平均）、ロス（タイムアウトの割合）。
    5. 段階は中央値で決まります：T0 神 ≤ 30 ms、T1 最強 ≤ 80 ms、T2 勝ち組 ≤ 150 ms、T3 モブ ≤ 250 ms、それ以上は T4 終わってる。おすすめに使う総合スコアは「中央値 + 2 × ジッター + ロスのペナルティ」なので、安定した 60 ms は不安定な 45 ms より上に来ます。

    HTTPS の計測が ICMP ping より体感に近い理由

    • あなたの通信と同じ道。Web、API、443 番のトンネル、ゲームのログイン、ダウンロードはどれも TCP です。多くのプロバイダは ICMP を別扱いで並べたり制限したり経路を変えたりするので、ping は良いのにページが重い、またはその逆がよくあります。
    • 制限で消されない。ルーターやクラウドは ICMP をよく制限・破棄しますが、公開 HTTPS エンドポイントは必ず応答します。
    • 実際の環境が入る。DNS、IPv4/IPv6 の選択、プロキシ、高速化サービスはブラウザの通信にも効くので、実際に得られる速さを測れます。
    • その代わり：毎回、少しだけ一定のサーバー処理時間が入ります。実測では AWS が 0–5 ms、Alibaba Cloud が約 8 ms、Huawei Cloud OBS が約 20 ms。100 ms を超えるような距離では無視できますが、ごく近いリージョンでは ping より少し大きく出ます。

    いつ測る：夜のピークを狙う

    • 家庭用回線は夜 20:00–23:00 がいちばん混み、海外向けはさらに顕著です。昼は T1 最強でも、夜にはモブまで落ちることがあります。
    • 昼に一度、ピークにもう一度測りましょう。保存された結果には「ピーク時間帯」の印が付き、結果から切り替えて比べられます。
    • 測定中は大きなダウンロード、動画、クラウド同期を止めてください。有線のほうが Wi‑Fi より正確。Wi‑Fi ならルーターの近くで。
    • モバイル回線では電波の強さで結果が変わります。実際に使う場所で測るのがいちばんです。

    こんなときに使えます

    • サーバー、ゲームサーバー、CDN のオリジンを契約する前に候補リージョンを絞り込む。
    • 同じ会社のリージョン同士、または同じ都市の別会社を比べる。
    • ゲーム、ビデオ会議、リモートデスクトップ、SSH に十分な安定性（ジッター、ロス）があるか確かめる。
    • プロキシ、高速化サービス、新しい回線プランが本当に効いているか、オン・オフで測り比べる。
    • カスタム接続先で、自分のサーバーや CDN を大手と並べて比べる。

    わからないこと

    • 1 か所だけの結果です。あなたの回線であって、ユーザーの回線ではありません。何人かのユーザーにも測ってもらい、書き出して比べましょう。
    • 測るのはエンドポイントで、将来のサーバーそのものではありません。各社のそのリージョンの公開 API やストレージを測ります。同じリージョンのサーバーは通常同じネットワークですが、プレミアム回線（CN2、BGP と単一キャリア、Lightsail と EC2 など）は違うことがあります。
    • 帯域、UDP、経路は測りません。往復時間だけで、ダウンロード速度、UDP のゲーム通信、途中の経路はわかりません。
    • ブラウザの影響。拡張機能、プロキシ、VPN、重いタブはノイズになります。重いタブは閉じて、このページを前面に。
    • Hetzner はブラウザから接続を保てないので、毎回ハンドシェイク込みの値です。一部の国では届かない接続先もあります。

    すべてのリクエストはあなたのブラウザから

    • このページは Cloudflare 上の静的ファイルだけです。バックエンドも登録も解析ツールもなく、結果をアップロードすることはありません。
    • テストのリクエストはすべてブラウザからクラウド事業者へ直接送られます。上のリクエストログか、開発者ツールの Network タブで 1 件ずつ確認できます。
    • ネットワーク情報は Cloudflare（speed.cloudflare.com/meta と /cdn-cgi/trace）から取得し、オプションの WebRTC チェックは stun.cloudflare.com に UDP の出口アドレスを問い合わせます。設定でオフにできます。
    • IPv4/IPv6 の判定では Cloudflare 以外の ipify.org と ident.me にも同時に問い合わせるので、どれか一つが遮断されていても IPv6 なしと誤判定しません。
    • 設定、カスタム接続先、最近の結果はこのブラウザのローカルストレージにだけ保存され、「テストデータを消去」で結果を削除できます。

    事業者にやさしく：制限もブロックも受けない

    公開エンドポイントに強く当てすぎると、事業者のレート制限や WAF に引っかかり、結果も狂います。そこでテストのペースはかなり控えめにしています：

    • 1 ホストにつき同時に 1 リクエスト、サンプルの間は 250–370 ms 空けます（1 ホストあたり毎秒最大 2–3 回）。
    • 1 社あたり同時に最大 2 ホスト、全体で最大 8 ホスト（既定は 4）。
    • 1 回のテストで 1 ホストあたり最大 21 リクエスト（ウォームアップ + 20）。連続モードはありません。
    • 3 回続けて失敗したホストは諦め、再試行し続けることはしません。
    • すべて匿名で Cookie も Referer もない「シンプルリクエスト」：プリフライトなし、応答は数百バイト、できるだけ HEAD、大きなファイルはダウンロードしません。

    全体の通信量は普通の Web ページを 1 枚開くより少ないくらいです。すべての接続先は匿名リクエストに普通に応答することを確認済みです（200、403、404 のどれでも計測には問題ありません）。

    プロキシや VPN を使っていたら？

    通信がプロキシを通ると、ブラウザが測るのは「あなた→プロキシ」と「プロキシ→クラウド」で、あなた自身の回線ではありません。ネットワーク表示では、出口がデータセンター、タイムゾーンと出口の国が違う、WARP がオン、WebRTC と HTTPS の出口が違う、といった典型的な兆候をチェックします。

    直結ルールを取得で、テスト用ホストだけを直結にして（Clash / Mihomo、Surge、Shadowrocket、Quantumult X、Loon、sing-box、Xray、SwitchyOmega、ドメイン一覧に対応）、再チェックしてください。プロキシ自体を測りたいなら、そのまま測れば、それがプロキシの本当の実力です。

    グラフの見方

    • 各行のバーは同じ目盛り（対数、2 ms から 3 秒）です。点は各サンプル、帯はサンプルの真ん中半分の範囲、縦線は中央値です。
    • 帯が細いほど安定、帯が太い・点がばらつくならジッターが大きい。赤い × はロスの回数です。
    • 行を開くと、各サンプルの推移、すべての統計、使った接続先が見られます。✓ は条件に合うものです。
